# YL-analysis安全分析系统用户手册

## 1. 系统简介

YL-analysis是一款基于大语言模型的代码安全分析系统，旨在帮助开发人员和安全团队快速识别、分析和修复代码中的安全漏洞。系统通过静态代码分析和调用图分析，能够检测多种常见的安全漏洞，如SQL注入、跨站脚本攻击、路径遍历等，并提供详细的漏洞分析报告和修复建议。

### 1.1 主要功能

- **项目管理**：上传、管理和删除待分析的代码项目
- **漏洞分析**：对项目进行安全漏洞扫描和分析
- **调用图分析**：可视化展示函数调用关系，追踪漏洞传播路径
- **漏洞报告**：提供详细的漏洞分析报告和修复建议
- **系统设置**：配置分析参数、API密钥等系统设置

### 1.2 系统要求

- 现代浏览器（Chrome, Firefox, Edge等最新版本）
- 网络连接（用于与后端API通信）
- 屏幕分辨率：最低1280x720，推荐1920x1080或更高

## 2. 快速入门

### 2.1 登录系统

1. 打开浏览器，访问系统URL（由管理员提供）
2. 如果系统配置了身份验证，请输入用户名和密码登录
3. 登录成功后，将进入系统概览页面

### 2.2 系统界面概览

系统界面主要由以下部分组成：

- **侧边栏**：提供主要功能导航，包括概览、项目管理、漏洞分析和设置
- **顶部栏**：显示当前页面标题和全局操作按钮
- **主内容区**：显示当前功能的详细内容
- **任务状态栏**：显示当前分析任务的状态和进度
- **日志面板**：显示系统日志和分析过程信息（可展开/折叠）

### 2.3 基本工作流程

使用YL-analysis进行安全分析的基本工作流程如下：

1. 在项目管理页面上传代码项目
2. 选择要分析的漏洞类型并启动分析
3. 等待分析完成（可在任务状态栏查看进度）
4. 在漏洞分析页面查看分析结果和调用图
5. 根据分析报告修复代码中的安全漏洞

## 3. 功能详解

### 3.1 概览页面

概览页面提供系统的整体状态和关键指标，包括：

- **统计卡片**：显示漏洞总数、分析文件数量、漏洞修复率等关键指标
- **漏洞分布图**：展示不同类型漏洞的分布情况
- **漏洞趋势图**：展示一段时间内漏洞数量的变化趋势
- **关键漏洞列表**：显示最近发现的高危漏洞
- **最近扫描记录**：显示最近的分析任务记录

#### 操作指南

1. 点击侧边栏的"概览"菜单进入概览页面
2. 将鼠标悬停在图表上可查看详细数据
3. 点击关键漏洞列表中的项目可跳转到相应的漏洞详情
4. 点击最近扫描记录中的项目可查看相应的分析结果

### 3.2 项目管理

项目管理页面用于管理待分析的代码项目，支持项目上传、删除和分析操作。

#### 3.2.1 上传项目

1. 点击侧边栏的"项目管理"菜单进入项目管理页面
2. 点击"上传项目"按钮，打开上传对话框
3. 输入项目名称
4. 点击"选择文件夹"按钮，选择要上传的代码文件夹
5. 点击"上传"按钮开始上传
6. 上传完成后，项目将显示在项目列表中

#### 3.2.2 删除项目

1. 在项目列表中找到要删除的项目
2. 点击项目行右侧的"删除"按钮
3. 在确认对话框中点击"确认"按钮
4. 项目将从列表中删除

#### 3.2.3 启动分析

1. 在项目列表中找到要分析的项目
2. 点击项目行右侧的"分析"按钮，打开分析对话框
3. 选择要分析的漏洞类型（可多选）
4. 点击"开始分析"按钮启动分析
5. 分析任务将在后台运行，可在任务状态栏查看进度

### 3.3 漏洞分析（调用图）

漏洞分析页面用于查看分析结果和调用图，追踪漏洞传播路径。

#### 3.3.1 查看调用图

1. 点击侧边栏的"漏洞分析"菜单进入漏洞分析页面
2. 从项目下拉列表中选择要查看的项目
3. 系统将加载该项目的调用图
4. 调用图将显示在左侧面板中，可通过鼠标操作进行缩放、平移和选择

#### 3.3.2 调用图操作

- **缩放**：使用鼠标滚轮或点击缩放控制按钮
- **平移**：按住鼠标左键拖动
- **选择节点**：点击节点可选中，节点详情将显示在右侧面板
- **选择边**：点击边可选中，相关节点将高亮显示
- **重置视图**：点击"重置"按钮恢复初始视图

#### 3.3.3 查看节点详情

1. 在调用图中点击节点
2. 右侧面板将显示节点详情，包括：
   - **漏洞分析**：显示与该节点相关的漏洞信息，包括漏洞类型、威胁评分、漏洞函数、利用方式、修复建议等
   - **节点详情**：显示节点基本信息，如ID、类型（源函数、汇函数、普通函数）等
   - **统计信息**：显示节点的入度和出度关系等统计数据

#### 3.3.4 分页浏览调用图

对于大型项目，调用图可能被分为多个页面：

1. 使用调用图上方的分页控件浏览不同页面
2. 点击页码按钮切换到指定页面
3. 点击"上一页"或"下一页"按钮浏览相邻页面

### 3.4 系统设置

系统设置页面用于配置系统参数、API密钥等设置。

#### 3.4.1 基本设置

1. 点击侧边栏的"设置"菜单进入设置页面
2. 在设置表单中可配置以下参数：
   - **测试模式**：启用/禁用测试模式
   - **重试次数**：设置API请求失败时的重试次数
   - **超时设置**：设置API请求的超时时间（秒）

#### 3.4.2 API设置

1. 在设置表单中配置以下API相关参数：
   - **OpenAI API密钥**：设置用于访问OpenAI服务的API密钥
   - **OpenAI API基础URL**：设置OpenAI API的基础URL
   - **模型名称**：设置使用的语言模型名称（如gpt-4、gpt-3.5-turbo等）

#### 3.4.3 保存设置

1. 完成设置修改后，点击"保存"按钮保存设置
2. 系统将显示保存成功的提示信息
3. 如需恢复默认设置，点击"重置"按钮

### 3.5 日志面板

日志面板显示系统日志和分析过程信息，帮助用户了解系统运行状态和诊断问题。

#### 3.5.1 查看日志

1. 点击顶部栏右侧的"日志"按钮展开日志面板
2. 日志面板将显示系统日志，按时间倒序排列
3. 不同类型的日志使用不同颜色标识：
   - **错误**：红色
   - **警告**：黄色
   - **信息**：蓝色
   - **调试**：灰色

#### 3.5.2 过滤日志

1. 在日志面板顶部的过滤下拉菜单中选择日志类型：
   - **全部**：显示所有类型的日志
   - **错误**：只显示错误日志
   - **警告**：只显示警告日志
   - **信息**：只显示信息日志
   - **调试**：只显示调试日志

#### 3.5.3 清空和导出日志

1. 点击"清空"按钮清空当前日志
2. 点击"导出"按钮将当前日志导出为文本文件

## 4. 高级功能

### 4.1 自定义分析

除了使用预设的漏洞类型进行分析外，系统还支持自定义分析配置：

1. 在项目管理页面点击"分析"按钮，打开分析对话框
2. 选择"自定义分析"选项
3. 配置自定义分析参数，如分析深度、超时时间等
4. 点击"开始分析"按钮启动自定义分析

### 4.2 批量分析

对于需要同时分析多个项目的情况，系统支持批量分析功能：

1. 在项目管理页面选中多个项目（按住Ctrl键点击多个项目）
2. 点击"批量分析"按钮，打开批量分析对话框
3. 选择要分析的漏洞类型
4. 点击"开始分析"按钮启动批量分析
5. 系统将依次分析选中的项目，可在任务状态栏查看进度

## 5. 故障排除

### 5.1 常见问题

#### 5.1.1 上传项目失败

**问题**：上传项目时出现错误或上传进度停滞。

**解决方案**：
1. 检查项目文件夹大小，确保不超过系统限制（通常为100MB）
2. 确保项目文件夹中不包含不支持的文件类型（如可执行文件、大型二进制文件等）
3. 尝试将项目分为多个小文件夹分别上传
4. 检查网络连接是否稳定

#### 5.1.2 分析任务长时间未完成

**问题**：分析任务启动后长时间未完成。

**解决方案**：
1. 检查项目大小，大型项目可能需要较长时间分析
2. 查看日志面板，了解分析进度和可能的错误
3. 如果分析时间超过30分钟，可以尝试停止当前任务并重新启动
4. 尝试减少选择的漏洞类型数量，分多次进行分析

#### 5.1.3 调用图无法加载

**问题**：漏洞分析页面的调用图无法加载或显示空白。

**解决方案**：
1. 确保项目已完成分析
2. 刷新页面重新加载调用图
3. 尝试使用不同的浏览器
4. 检查浏览器控制台是否有错误信息
5. 确保浏览器已启用JavaScript和WebGL

#### 5.1.4 设置保存失败

**问题**：系统设置无法保存或保存后未生效。

**解决方案**：
1. 确保填写的设置值符合要求（如API密钥格式正确）
2. 检查网络连接是否稳定
3. 清除浏览器缓存后重试
4. 尝试使用不同的浏览器

## 6. 最佳实践

### 6.1 项目管理最佳实践

- **项目命名**：使用有意义的名称，包含版本信息和日期
- **项目组织**：将相关项目分组管理，便于批量操作
- **定期清理**：删除不再需要的项目，保持项目列表整洁
- **增量分析**：对于大型项目，可以只上传修改的部分进行增量分析

### 6.2 分析策略最佳实践

- **分阶段分析**：先选择高危漏洞类型进行分析，再逐步扩展到其他类型
- **定期分析**：建立定期分析计划，如每周或每次代码提交后
- **关注重点**：优先关注高危漏洞和关键组件
- **结合代码审查**：将自动分析结果与人工代码审查结合，提高准确性

### 6.3 结果处理最佳实践

- **优先级排序**：根据漏洞严重程度和影响范围排序处理
- **记录修复**：记录漏洞修复过程和方法，形成知识库
- **验证修复**：修复漏洞后重新分析，确认修复有效
- **团队共享**：将分析结果和修复经验共享给团队成员，提高整体安全意识

## 7. 术语表

| 术语 | 定义 |
|------|------|
| 调用图 | 可视化展示函数之间调用关系的图形 |
| 源函数 | 接收外部输入的函数，可能是漏洞的起点 |
| 汇函数 | 执行敏感操作的函数，可能是漏洞的终点 |
| 污点分析 | 追踪不可信数据在程序中的流动路径 |
| 威胁评分 | 衡量漏洞严重程度的指标，通常为1-10的数值 |
| SQL注入 | 通过在输入中插入SQL代码来操纵数据库的漏洞 |
| XSS | 跨站脚本攻击，通过在网页中注入恶意脚本的漏洞 |
| 路径遍历 | 通过操纵文件路径参数访问受限文件的漏洞 |
| API密钥 | 用于访问第三方服务的身份验证凭证 |
