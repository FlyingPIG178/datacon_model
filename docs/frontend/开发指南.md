# YL-analysis安全分析前端开发指南

本文档为开发者提供YL-analysis前端项目的开发、调试和扩展指导。

## 环境搭建

### 开发环境要求

- Node.js 16.x 或更高版本
- npm 8.x 或更高版本
- 现代浏览器（Chrome, Firefox, Edge等）

### 安装步骤

1. 克隆代码仓库

```bash
git clone <repository-url>
cd YLfrontend
```

2. 安装依赖

```bash
npm install
```

3. 启动开发服务器

```bash
npm run dev
```

开发服务器将在`http://localhost:3000`启动（或其他可用端口）。

## 开发规范

### 代码风格

项目使用ESLint和Prettier进行代码风格检查和格式化。请确保您的代码符合项目的代码风格规范。

```bash
# 运行代码风格检查
npm run lint

# 自动修复代码风格问题
npm run lint:fix

# 格式化代码
npm run format
```

### 命名规范

- **文件命名**：
  - 组件文件使用PascalCase（如`GraphViewer.vue`）
  - 非组件文件使用kebab-case（如`api-service.js`）
  
- **组件命名**：
  - 组件名使用PascalCase（如`GraphViewer`）
  - 基础组件以`App`前缀开头（如`AppCard`）
  
- **变量命名**：
  - 使用camelCase（如`graphData`）
  - 布尔值变量使用`is`/`has`前缀（如`isLoading`）
  
- **常量命名**：
  - 使用UPPER_SNAKE_CASE（如`MAX_RETRY_COUNT`）

### 组件开发规范

- 组件应遵循单一职责原则
- 使用`defineProps`和`defineEmits`进行属性和事件定义
- 使用`<script setup>`语法
- 组件样式使用`scoped`属性隔离

示例：

```vue
<template>
  <div class="component-container">
    <!-- 组件内容 -->
  </div>
</template>

<script setup>
import { ref, computed, onMounted } from 'vue'

// 定义props
const props = defineProps({
  data: {
    type: Object,
    required: true
  },
  loading: {
    type: Boolean,
    default: false
  }
})

// 定义事件
const emit = defineEmits(['update', 'select'])

// 组件逻辑
const localData = ref({})

onMounted(() => {
  // 初始化逻辑
})

// 计算属性
const computedValue = computed(() => {
  // 计算逻辑
  return result
})

// 方法
function handleAction() {
  // 处理逻辑
  emit('update', localData.value)
}
</script>

<style scoped>
.component-container {
  /* 组件样式 */
}
</style>
```

## 状态管理

项目使用Pinia进行状态管理。主要的store包括：

- **logStore**: 管理系统日志
- **settingsStore**: 管理系统设置
- **projectStore**: 管理项目数据
- **analysisStore**: 管理分析状态和结果

### 创建新的Store

```javascript
// src/stores/exampleStore.js
import { defineStore } from 'pinia'

export const useExampleStore = defineStore('example', {
  state: () => ({
    // 状态定义
    items: [],
    loading: false,
    error: null
  }),
  getters: {
    // 计算属性
    itemCount: (state) => state.items.length,
    hasError: (state) => state.error !== null
  },
  actions: {
    // 方法
    async fetchItems() {
      this.loading = true
      try {
        // 异步操作
        this.items = await api.getItems()
        this.error = null
      } catch (error) {
        this.error = error.message
      } finally {
        this.loading = false
      }
    },
    addItem(item) {
      this.items.push(item)
    }
  }
})
```

### 在组件中使用Store

```vue
<script setup>
import { useExampleStore } from '@/stores/exampleStore'

const exampleStore = useExampleStore()

// 访问状态
const items = exampleStore.items
const loading = exampleStore.loading

// 调用action
function loadData() {
  exampleStore.fetchItems()
}

// 使用getter
const itemCount = exampleStore.itemCount
</script>
```

## API集成

项目使用Axios进行API请求。API服务位于`src/components/api.js`。

### 添加新的API请求

```javascript
// src/components/api.js
import axios from 'axios'

const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:5000',
  timeout: 60000,
})

// 现有API函数...

// 添加新的API函数
export function newFeatureApi(params) {
  return api.post('/api/new-feature', params)
}

export function getNewFeatureData(id) {
  return api.get(`/api/new-feature/${id}`)
}
```

### 在组件中使用API

```vue
<script setup>
import { ref } from 'vue'
import { newFeatureApi, getNewFeatureData } from '@/components/api'
import { useLogStore } from '@/stores/logStore'

const logStore = useLogStore()
const data = ref(null)
const loading = ref(false)
const error = ref(null)

async function fetchData(id) {
  loading.value = true
  try {
    const response = await getNewFeatureData(id)
    data.value = response.data
    logStore.addLog({
      level: 'info',
      message: `成功获取数据: ${id}`
    })
  } catch (err) {
    error.value = err.message
    logStore.addLog({
      level: 'error',
      message: `获取数据失败: ${err.message}`
    })
  } finally {
    loading.value = false
  }
}
</script>
```

## 常见问题与解决方案

### 跨域问题

**问题**：前端无法访问后端API，出现跨域错误。

**解决方案**：
1. 在开发环境中配置Vite代理：

```javascript
// vite.config.js
export default {
  // ...
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:5000',
        changeOrigin: true
      }
    }
  }
}
```

2. 在生产环境中配置Nginx代理（见部署配置）

### 状态管理问题

**问题**：组件间状态共享和同步困难。

**解决方案**：
1. 使用Pinia集中管理共享状态
2. 使用组件通信（props和events）传递局部状态
3. 对于复杂组件树，考虑使用provide/inject API

```javascript
// 父组件
import { provide } from 'vue'

provide('key', value)

// 子组件或孙组件
import { inject } from 'vue'

const value = inject('key')
```

### 性能问题

**问题**：大数据量渲染导致页面卡顿。

**解决方案**：
1. 使用虚拟滚动处理大列表
2. 实现分页加载
3. 使用Web Worker处理复杂计算
4. 优化组件渲染（v-once, v-memo等）

```vue
<!-- 使用v-memo优化列表渲染 -->
<div v-for="item in list" :key="item.id" v-memo="[item.id, item.status]">
  <!-- 只有当id或status变化时才会重新渲染 -->
  {{ item.name }}
</div>
```

## 贡献指南

### 提交规范

项目使用Conventional Commits规范进行提交信息格式化：

```
<type>(<scope>): <subject>

<body>

<footer>
```

常用的type类型：
- feat: 新功能
- fix: 修复bug
- docs: 文档更新
- style: 代码风格修改（不影响功能）
- refactor: 代码重构
- perf: 性能优化
- test: 测试相关
- chore: 构建过程或辅助工具变动

示例：
```
feat(call-graph): 添加节点搜索功能

实现了在调用图中搜索特定节点的功能，包括：
- 关键字搜索
- 高亮匹配节点
- 搜索结果导航

Closes #123
```

### 分支管理

- `main`: 主分支，保持稳定可发布状态
- `develop`: 开发分支，集成最新功能
- `feature/*`: 功能分支，用于开发新功能
- `bugfix/*`: 修复分支，用于修复bug
- `release/*`: 发布分支，用于版本发布准备

### Pull Request流程

1. Fork项目仓库
2. 创建功能分支
3. 提交更改
4. 确保测试通过
5. 提交Pull Request
6. 等待代码审查和合并
