# YL-analysis安全分析前端部署指南

本文档提供YL-analysis前端项目的部署指南，包括环境要求、部署步骤和配置说明。

## 环境要求

### 系统要求

- 操作系统：Linux（推荐Ubuntu 20.04+）、Windows Server 2016+或macOS
- CPU：2核或更高
- 内存：4GB或更高
- 磁盘空间：至少1GB可用空间

### 软件要求

- Node.js 16.x或更高版本
- npm 8.x或更高版本
- Nginx 1.18.0或更高版本（用于生产环境部署）
- Docker 20.10.x或更高版本（可选，用于容器化部署）

## 部署方式

根据不同的需求和环境，YL-analysis前端可以通过以下几种方式部署：

1. 标准部署（构建静态文件 + Web服务器）
2. Docker容器化部署
3. 开发环境部署

## 标准部署

### 步骤1：获取源代码

```bash
# 克隆代码仓库
git clone <repository-url>
cd YLfrontend

# 切换到稳定版本（可选）
git checkout v1.0.0  # 替换为实际的版本标签
```

### 步骤2：安装依赖

```bash
npm install
```

### 步骤3：配置环境变量

创建`.env.production`文件，配置生产环境变量：

```
VITE_API_BASE_URL=https://api.example.com  # 替换为实际的后端API地址
```

### 步骤4：构建项目

```bash
npm run build
```

构建完成后，将在`dist`目录生成静态文件。

### 步骤5：配置Web服务器

#### Nginx配置

创建Nginx配置文件`/etc/nginx/conf.d/yl-frontend.conf`：

```nginx
server {
    listen 80;
    server_name your-domain.com;  # 替换为实际的域名
    root /path/to/YLfrontend/dist;  # 替换为dist目录的实际路径
    index index.html;
    
    # 启用gzip压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;
    
    # 缓存静态资源
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
    
    # 处理前端路由
    location / {
        try_files $uri $uri/ /index.html;
    }
    
    # 代理API请求到后端服务
    location /api/ {
        proxy_pass https://api.example.com/;  # 替换为实际的后端API地址
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    
    # 安全相关配置
    add_header X-Content-Type-Options nosniff;
    add_header X-XSS-Protection "1; mode=block";
    add_header X-Frame-Options "SAMEORIGIN";
}
```

#### Apache配置（可选）

如果使用Apache作为Web服务器，创建`.htaccess`文件并放置在`dist`目录：

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /index.html [L]
</IfModule>

# 启用缓存
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType text/css "access plus 1 month"
  ExpiresByType application/javascript "access plus 1 month"
  ExpiresByType image/jpeg "access plus 1 month"
  ExpiresByType image/png "access plus 1 month"
  ExpiresByType image/svg+xml "access plus 1 month"
</IfModule>

# 安全相关配置
<IfModule mod_headers.c>
  Header set X-Content-Type-Options "nosniff"
  Header set X-XSS-Protection "1; mode=block"
  Header set X-Frame-Options "SAMEORIGIN"
</IfModule>
```

### 步骤6：启动Web服务器

```bash
# 检查Nginx配置
sudo nginx -t

# 重启Nginx
sudo systemctl restart nginx
```

## Docker容器化部署

### 步骤1：创建Dockerfile

在项目根目录创建`Dockerfile`：

```dockerfile
# 构建阶段
FROM node:16-alpine as build-stage
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
ARG VITE_API_BASE_URL=http://localhost:5000
ENV VITE_API_BASE_URL=${VITE_API_BASE_URL}
RUN npm run build

# 生产阶段
FROM nginx:alpine as production-stage
COPY --from=build-stage /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### 步骤2：创建Nginx配置文件

在项目根目录创建`nginx.conf`：

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;
    
    # 启用gzip压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;
    
    # 处理前端路由
    location / {
        try_files $uri $uri/ /index.html;
    }
    
    # 代理API请求到后端服务
    location /api/ {
        proxy_pass ${API_URL};
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    
    # 安全相关配置
    add_header X-Content-Type-Options nosniff;
    add_header X-XSS-Protection "1; mode=block";
    add_header X-Frame-Options "SAMEORIGIN";
}
```

### 步骤3：创建Docker Compose配置

在项目根目录创建`docker-compose.yml`：

```yaml
version: '3'

services:
  frontend:
    build:
      context: .
      args:
        - VITE_API_BASE_URL=${API_URL:-http://backend:5000}
    ports:
      - "80:80"
    environment:
      - API_URL=${API_URL:-http://backend:5000}
    depends_on:
      - backend
    networks:
      - app-network

  backend:
    image: yl-backend:latest  # 替换为实际的后端镜像
    ports:
      - "5000:5000"
    environment:
      - NODE_ENV=production
    networks:
      - app-network

networks:
  app-network:
    driver: bridge
```

### 步骤4：构建和运行Docker容器

```bash
# 使用Docker Compose启动服务
docker-compose up -d

# 或者单独构建和运行前端容器
docker build -t yl-frontend .
docker run -d -p 80:80 -e API_URL=http://api.example.com --name yl-frontend yl-frontend
```

## 多环境部署

### 环境变量配置

Vite支持多环境配置，可以创建不同的环境配置文件：

- `.env`：所有环境共享的变量
- `.env.development`：开发环境变量
- `.env.production`：生产环境变量
- `.env.staging`：预发布环境变量

示例配置：

```
# .env.production
VITE_API_BASE_URL=https://api.example.com
VITE_APP_TITLE=YL-analysis

# .env.staging
VITE_API_BASE_URL=https://staging-api.example.com
VITE_APP_TITLE=YL-analysis (Staging)
```

### 构建不同环境版本

```bash
# 构建生产环境版本
npm run build

# 构建预发布环境版本
npm run build:staging
```

在`package.json`中添加相应的脚本：

```json
{
  "scripts": {
    "build": "vite build",
    "build:staging": "vite build --mode staging"
  }
}
```

## 持续集成/持续部署 (CI/CD)

### GitHub Actions配置

在项目根目录创建`.github/workflows/deploy.yml`：

```yaml
name: Deploy

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v2
    
    - name: Setup Node.js
      uses: actions/setup-node@v2
      with:
        node-version: '16'
        cache: 'npm'
    
    - name: Install dependencies
      run: npm install
    
    - name: Build
      run: npm run build
      env:
        VITE_API_BASE_URL: ${{ secrets.API_URL }}
    
    - name: Deploy to server
      uses: appleboy/scp-action@master
      with:
        host: ${{ secrets.HOST }}
        username: ${{ secrets.USERNAME }}
        key: ${{ secrets.SSH_KEY }}
        source: "dist/"
        target: "/var/www/yl-frontend"
        strip_components: 1
    
    - name: Restart Nginx
      uses: appleboy/ssh-action@master
      with:
        host: ${{ secrets.HOST }}
        username: ${{ secrets.USERNAME }}
        key: ${{ secrets.SSH_KEY }}
        script: sudo systemctl restart nginx
```

### GitLab CI/CD配置

在项目根目录创建`.gitlab-ci.yml`：

```yaml
stages:
  - build
  - deploy

build:
  stage: build
  image: node:16-alpine
  script:
    - npm install
    - npm run build
  artifacts:
    paths:
      - dist/
  only:
    - main

deploy:
  stage: deploy
  image: alpine:latest
  before_script:
    - apk add --no-cache openssh-client
    - mkdir -p ~/.ssh
    - echo "$SSH_PRIVATE_KEY" > ~/.ssh/id_rsa
    - chmod 600 ~/.ssh/id_rsa
    - echo -e "Host *\n\tStrictHostKeyChecking no\n\n" > ~/.ssh/config
  script:
    - scp -r dist/* $SERVER_USER@$SERVER_HOST:$SERVER_PATH
    - ssh $SERVER_USER@$SERVER_HOST "sudo systemctl restart nginx"
  only:
    - main
```

## 性能优化

### 静态资源优化

1. **启用Gzip压缩**：

```nginx
# Nginx配置
gzip on;
gzip_comp_level 5;
gzip_min_length 256;
gzip_proxied any;
gzip_vary on;
gzip_types
  application/javascript
  application/json
  application/xml
  text/css
  text/plain
  text/xml;
```

2. **配置缓存策略**：

```nginx
# Nginx配置
location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg)$ {
    expires 30d;
    add_header Cache-Control "public, no-transform";
}
```

3. **使用CDN**：

将静态资源部署到CDN，修改`vite.config.js`：

```javascript
export default {
  base: process.env.NODE_ENV === 'production' ? 'https://cdn.example.com/' : '/',
  // 其他配置...
}
```

### 构建优化

1. **代码分割**：

```javascript
// vite.config.js
export default {
  build: {
    rollupOptions: {
      output: {

          vendor: ['vue', 'vue-router', 'pinia'],
```

2. **启用源码映射**：


## 安全配置

### HTTPS配置

#### 使用Let's Encrypt获取SSL证书

```bash
# 安装Certbot
sudo apt-get update
sudo apt-get install certbot python3-certbot-nginx

# 获取证书并自动配置Nginx
sudo certbot --nginx -d your-domain.com
```

#### 手动配置Nginx HTTPS

```nginx
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;
    
    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers on;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    
    # 其他配置...
}
```

### 安全响应头配置

```nginx
# Nginx配置
add_header X-Content-Type-Options nosniff;
add_header X-XSS-Protection "1; mode=block";
add_header X-Frame-Options "SAMEORIGIN";
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self' https://api.example.com;";
add_header Referrer-Policy "strict-origin-when-cross-origin";
```

## 监控与日志

### Nginx访问日志配置

```nginx
log_format detailed '$remote_addr - $remote_user [$time_local] '
                    '"$request" $status $body_bytes_sent '
                    '"$http_referer" "$http_user_agent" '
                    '$request_time $upstream_response_time $pipe';

access_log /var/log/nginx/yl-frontend-access.log detailed;
error_log /var/log/nginx/yl-frontend-error.log;
```

### 日志轮转配置

创建`/etc/logrotate.d/yl-frontend`：

```
/var/log/nginx/yl-frontend-*.log {
    daily
    missingok
    rotate 14
    compress
    delaycompress
    notifempty
    create 0640 www-data adm
    sharedscripts
    postrotate
        [ -s /run/nginx.pid ] && kill -USR1 `cat /run/nginx.pid`
    endscript
}
```

## 故障排除

### 常见问题与解决方案

#### 1. 页面加载404错误

**问题**：部署后访问非根路径的URL时返回404错误。

**解决方案**：确保Web服务器配置了正确的重写规则，将所有请求重定向到index.html。

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

#### 2. API请求跨域错误

**问题**：浏览器控制台显示跨域请求错误。

**解决方案**：

1. 配置后端CORS支持
2. 使用Nginx代理API请求

```nginx
location /api/ {
    proxy_pass https://api.example.com/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

#### 3. 静态资源加载失败

**问题**：CSS、JS或图片资源加载失败。

**解决方案**：

1. 检查资源路径是否正确
2. 确保`vite.config.js`中的`base`配置正确

```javascript
export default {
  base: '/',  // 或者指定子路径，如 '/app/'
  // 其他配置...
}
```

#### 4. 环境变量未生效

**问题**：环境变量在构建后未生效。

**解决方案**：

1. 确保环境变量以`VITE_`前缀开头
2. 检查构建命令是否指定了正确的模式

```bash
npm run build -- --mode production
```

## 维护与更新

### 版本更新流程

1. **备份当前版本**：

```bash
cp -r /var/www/yl-frontend /var/www/yl-frontend-backup-$(date +%Y%m%d)
```

2. **拉取最新代码**：

```bash
git pull origin main
```

3. **安装依赖并构建**：

```bash
npm install
npm run build
```

4. **部署新版本**：

```bash
rm -rf /var/www/yl-frontend/*
cp -r dist/* /var/www/yl-frontend/
```

5. **重启Web服务器**：

```bash
sudo systemctl restart nginx
```

### 回滚流程

如果新版本出现问题，可以快速回滚到之前的版本：

```bash
rm -rf /var/www/yl-frontend/*
cp -r /var/www/yl-frontend-backup-YYYYMMDD/* /var/www/yl-frontend/
sudo systemctl restart nginx
```
