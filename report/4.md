## 4. 前端实现

### 4.1 技术架构

YL-analysis 前端采用现代化的技术栈和架构设计，以提供高效、流畅的用户体验。前端技术选型充分考虑了开发效率、性能表现和用户体验等因素，选择了以下核心技术：

- **Vue3**：采用 Vue.js 3 作为核心框架，利用其 Composition API、更好的 TypeScript 集成、更小的包体积和改进的响应式系统等优势，提升开发效率和应用性能。

- **Element Plus**：选择 Element Plus 作为 UI 组件库，提供丰富、美观且易用的组件，确保界面设计的专业性和一致性。

- **Pinia**：使用 Vue 官方推荐的状态管理库 Pinia，相比 Vuex 更轻量、更直观，并提供更好的 TypeScript 支持。

- **Vue Router**：采用 Vue 官方路由管理器，支持嵌套路由、动态路由、路由守卫等功能，实现页面间的无缝导航。

前端架构采用模块化和组件化设计，将不同功能区域划分为独立的模块，每个模块又由多个可复用的组件构成。这种设计方式提高了代码的可维护性和可扩展性，同时也便于团队协作开发。

### 4.2 系统结构

YL-analysis 前端系统整体分为 4 个主要页面，每个页面负责特定的功能区域：

#### 4.2.1 概览页面

概览页面是系统的首页，提供项目整体情况的可视化展示，包括漏洞统计、文件分析情况、漏洞类型分布等信息，帮助用户快速了解系统状态和分析结果。

**主要组件**：
- 统计卡片：显示关键指标
- 图表组件：使用 ECharts 展示漏洞分布和趋势
- 数据表格：展示关键漏洞和最近扫描

**数据来源**：
- 漏洞统计数据：通过 API 从后端获取
- 图表数据：基于漏洞分析结果生成
- 最近扫描记录：从后端获取历史扫描记录

**交互功能**：
- 点击"分析更多"按钮：跳转到漏洞分析页面
- 点击"查看详情"按钮：查看特定漏洞或扫描的详细信息

#### 4.2.2 项目管理页面

项目管理页面负责管理待分析的代码项目，支持项目上传、删除、查看和分析操作，是用户进行漏洞分析的入口。

**主要组件**：
- 项目表格：展示项目列表和操作按钮
- 上传对话框：提供项目上传功能
- 分析对话框：配置分析参数并启动分析

**核心功能**：

**项目列表**：
- 展示所有已上传的项目
- 显示项目名称、创建时间等信息
- 提供分析和删除操作

**项目上传**：
- 支持选择本地文件夹上传
- 自动处理文件上传过程
- 显示上传进度和结果

**项目分析**：
- 选择漏洞类型进行分析
- 启动分析任务
- 显示分析状态和进度

**API 接口**：
- `listChallenges()`：获取项目列表
- `deleteProject(projectName)`：删除指定项目
- `uploadFolder(formData)`：上传项目文件夹
- `startAnalysis(projectName, vulType)`：开始分析项目

#### 4.2.3 漏洞分析页面

漏洞分析页面是系统的核心功能，通过调用图可视化展示函数调用关系，并提供漏洞详情查看、节点信息展示等功能，帮助用户理解漏洞的传播路径和影响范围。

**主要组件**：
- 图形查看器：实现交互式网络图展示
- 节点详情：显示选中节点的详细信息

**核心功能**：

**调用图可视化**：
- 使用 vis-network 库实现交互式网络图
- 支持节点拖拽、缩放、选择等操作
- 不同类型节点使用不同颜色标识（源函数、汇函数、普通函数）

**节点详情展示**：
- 显示选中节点的详细信息
- 展示节点的入度和出度关系
- 提供漏洞分析结果查看

**漏洞信息展示**：
- 显示漏洞类型、威胁评分、利用方式等信息
- 提供修复建议和分析理由
- 展示污点参数和污点操作

**API 接口**：
- `getCallGraph(projectName)`：获取项目调用图数据

#### 4.2.4 设置页面

设置页面允许用户配置系统参数，包括 LLM 服务设置、API 密钥、分析参数等，为漏洞分析提供必要的配置支持。

**主要组件**：
- 设置表单：提供各项设置的配置界面

**可配置项**：
- **测试模式**：启用/禁用测试模式
- **重试次数**：设置 API 调用失败时的重试次数
- **超时设置**：设置 API 调用超时时间
- **OpenAI API 密钥**：设置用于 LLM 服务的 API 密钥
- **OpenAI API 基础 URL**：设置 API 服务的基础 URL
- **模型名称**：设置使用的 LLM 模型名称

**数据验证**：
- 重试次数：必须在 1-20 之间
- 超时设置：必须在 1-3600 秒之间
- 模型名称：不能为空

**API 接口**：
- `getSettings()`：获取当前设置
- `saveSettings(settings)`：保存设置

### 4.3 组件设计

YL-analysis 前端采用组件化设计，将界面拆分为多个可复用的组件，提高代码的可维护性和可扩展性。主要组件包括：

#### 4.3.1 布局组件

- **AppHeader**：应用顶部导航栏，提供页面切换和系统信息展示
- **AppSidebar**：应用侧边栏，提供主要功能区域的导航
- **AppFooter**：应用底部栏，显示版权信息和系统状态
- **LogPanel**：日志面板，实时显示系统日志信息

#### 4.3.2 项目管理组件

- **ProjectTable**：项目列表表格，展示项目信息和操作按钮
- **UploadDialog**：项目上传对话框，提供文件选择和上传功能
- **AnalysisDialog**：分析配置对话框，提供漏洞类型选择和分析启动功能

#### 4.3.3 漏洞分析组件

- **GraphViewer**：调用图可视化组件，展示函数调用关系
- **NodeDetails**：节点详情组件，显示选中节点的详细信息
- **VulnInfo**：漏洞信息组件，展示漏洞分析结果

#### 4.3.4 通用组件

- **StatCard**：统计卡片，展示关键指标
- **ChartComponent**：图表组件，基于 ECharts 实现各类图表展示
- **ConfirmDialog**：确认对话框，用于危险操作的二次确认
- **LoadingSpinner**：加载指示器，显示操作进行中的状态

### 4.4 状态管理

YL-analysis 前端使用 Pinia 进行状态管理，将应用状态划分为多个独立的 store，每个 store 负责管理特定功能区域的状态。主要的 store 包括：

#### 4.4.1 项目 Store (projectStore)

管理项目相关的状态，包括项目列表、当前选中的项目等。

**主要状态**：
- `projects`：项目列表
- `currentProject`：当前选中的项目

**主要操作**：
- `fetchProjects()`：获取项目列表
- `deleteProject(projectName)`：删除项目
- `uploadProject(formData)`：上传项目
- `setCurrentProject(project)`：设置当前项目

#### 4.4.2 分析 Store (analysisStore)

管理分析任务相关的状态，包括分析状态、分析结果等。

**主要状态**：
- `analysisStatus`：当前分析状态
- `analysisResults`：分析结果
- `callGraph`：调用图数据

**主要操作**：
- `startAnalysis(projectName, vulType)`：启动分析任务
- `stopAnalysis()`：停止分析任务
- `fetchAnalysisStatus()`：获取分析状态
- `fetchCallGraph(projectName)`：获取调用图数据

#### 4.4.3 设置 Store (settingsStore)

管理系统设置相关的状态。

**主要状态**：
- `settings`：系统设置

**主要操作**：
- `fetchSettings()`：获取系统设置
- `saveSettings(settings)`：保存系统设置

#### 4.4.4 日志 Store (logStore)

管理系统日志相关的状态。

**主要状态**：
- `logs`：日志列表

**主要操作**：
- `addLog(log)`：添加日志
- `clearLogs()`：清空日志

### 4.6 API 通信

YL-analysis 前端使用 Axios 进行 API 通信，封装了一系列 API 请求函数，简化了与后端的交互。主要的 API 请求函数包括：

```javascript
// 项目管理 API
export const listChallenges = () => {
  return axios.get('/api/list-challenges')
}

export const deleteProject = (projectName) => {
  return axios.delete(`/api/delete-project/${projectName}`)
}

export const uploadFolder = (formData) => {
  return axios.post('/api/upload-folder', formData)
}

// 分析管理 API
export const startAnalysis = (projectName, vulType) => {
  return axios.post('/api/start-analysis', { project_name: projectName, vuln_type: vulType })
}

export const getAnalysisStatus = () => {
  return axios.get('/api/analysis-status')
}

export const stopAnalysis = () => {
  return axios.post('/api/stop-analysis')
}

export const getCallGraph = (projectName) => {
  return axios.get(`/api/call-graph/${projectName}`)
}

// 设置管理 API
export const getSettings = () => {
  return axios.get('/api/settings')
}

export const saveSettings = (settings) => {
  return axios.post('/api/settings', settings)
}
```

### 4.7 WebSocket 通信

YL-analysis 前端使用 WebSocket 实现与后端的实时通信，主要用于接收分析状态更新和系统日志。WebSocket 通信的实现如下：

```javascript
export const setupWebSocket = (store) => {
  const ws = new WebSocket(`ws://${window.location.host}/ws`)

  ws.onmessage = (event) => {
    const data = JSON.parse(event.data)

    if (data.type === 'log') {
      store.dispatch('log/addLog', data.message)
    } else if (data.type === 'analysis_status') {
      store.dispatch('analysis/updateStatus', data.status)
    }
  }

  ws.onclose = () => {
    setTimeout(() => {
      setupWebSocket(store)
    }, 1000)
  }

  return ws
}
```

通过 WebSocket 通信，前端能够实时接收后端的状态更新和日志信息，提供更好的用户体验。
