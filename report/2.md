## 2. 系统架构

### 2.1 整体架构

YL-analysis 系统采用分层架构设计，主要包括以下几层：

1. **表示层**：前端用户界面，负责展示数据和接收用户输入
2. **API 层**：后端 API 接口，负责处理前端请求和返回数据
3. **服务层**：核心业务逻辑，包括漏洞分析、任务管理等
4. **数据层**：文件系统存储，包括项目文件、配置文件和日志文件

系统整体架构如图所示，清晰展示了各组件之间的关系和数据流向。前端通过 HTTP 请求与后端 API 交互，API 层接收请求并调用相应的服务层组件处理业务逻辑，服务层组件根据需要访问数据层获取或存储数据。整个架构设计遵循关注点分离原则，各层之间通过明确定义的接口进行通信，确保系统的可维护性和可扩展性。

### 2.2 核心组件

#### 2.2.1 服务管理器 (ServiceManager)

服务管理器是系统的核心组件，负责初始化和协调所有 API 服务。它采用单例模式实现，确保整个应用中只有一个服务管理器实例。

**主要职责**：
- 初始化 aiohttp 应用
- 设置路由
- 管理应用的启动和关闭回调
- 确保必要的目录结构存在

**关键接口**：
- `create_app()`：创建 aiohttp 应用
- `register_startup_callback()`：注册启动回调函数
- `register_shutdown_callback()`：注册关闭回调函数

#### 2.2.2 路由系统

系统采用模块化的路由管理方式，所有路由管理器都继承自 `RouterBase` 抽象基类。

**主要路由模块**：
- **AnalysisRouter**: 处理代码分析相关的 API 请求
- **ProjectsRouter**: 管理项目相关的 API 请求
- **SettingsRouter**: 处理系统设置相关的 API 请求
- **StaticRouter**: 管理静态文件的路由

**关键接口**：
- `add_routes(app)`：向应用添加路由

#### 2.2.3 分析队列管理器 (AnalysisQueueManager)

分析队列管理器负责管理和执行代码分析任务。它实现了一个任务队列和工作线程，可以按顺序处理分析请求。

**主要功能**：
- 添加分析任务到队列
- 管理任务的执行状态
- 通知监听器任务状态变化
- 支持终止正在执行的任务

**关键接口**：
- `add_task(task)`：添加分析任务
- `get_status()`：获取队列和任务状态
- `add_listener(listener)`：添加状态更新监听器
- `clear_queue()`：清空任务队列
- `stop_current_task()`：停止当前任务

#### 2.2.4 漏洞检测器 (VulnDetector)

漏洞检测器是系统的核心分析组件，负责对代码进行漏洞分析。

**主要功能**：
- 加载和解析代码文件
- 分析函数语义
- 生成调用图
- 识别潜在的漏洞链
- 评估漏洞风险

**关键接口**：
- `analyze_challenge(project_dir, vuln_type, task)`：分析指定项目的漏洞
- `run_single_challenge(challenge, task)`：运行单个项目的分析流程
- `get_challenge(project_dir, vuln_type)`：获取 Challenge 对象

#### 2.2.5 终端服务 (TerminalService)

终端服务负责管理系统日志，并支持将日志实时推送给监听器。

**主要功能**：
- 收集系统日志
- 管理日志监听器
- 推送日志更新

**关键接口**：
- `add_listener(listener)`：添加日志监听器
- `remove_listener(listener)`：移除日志监听器

### 2.3 系统流程

#### 2.3.1 项目上传和管理流程

1. 用户通过前端界面上传项目文件
2. 前端发送 POST 请求到 `/api/upload-challenge`
3. 后端接收文件并保存到项目目录
4. 后端返回成功响应
5. 前端更新项目列表

#### 2.3.2 漏洞分析流程

1. 用户通过前端界面选择项目和漏洞类型
2. 用户启动分析任务
3. 前端发送 POST 请求到 `/api/start-analysis`
4. 后端创建分析任务并加入队列
5. 分析队列管理器按顺序执行任务
6. 漏洞检测器加载项目代码并进行分析
   - 解析项目文件和函数
   - 分析函数语义
   - 生成函数调用图
   - 识别潜在的漏洞链
   - 评估漏洞风险
7. 分析结果保存到结果目录
8. 前端通过 WebSocket 接收实时分析状态
9. 分析完成后，前端获取并展示分析结果

#### 2.3.3 实时日志流程

1. 系统输出日志或终端消息
2. 终端服务捕获输出，保存到日志文件
3. 终端服务通知所有注册的监听器
4. 前端通过 WebSocket 接收日志消息
5. 前端实时显示日志消息

### 2.4 技术特点

- **异步处理**：使用 aiohttp 实现异步 API 服务，提高系统并发处理能力
- **模块化设计**：各组件职责明确，便于维护和扩展
- **线程安全**：使用锁机制确保队列操作的线程安全
- **事件通知**：使用监听器模式实现状态更新通知
- **单例模式**：关键管理器采用单例模式避免资源冲突
- **基于 LLM 的分析**：利用大语言模型进行代码语义分析，提高漏洞检测的准确性
- **可扩展的漏洞类型**：支持多种漏洞类型的检测，易于扩展新的漏洞类型
- **实时状态更新**：通过 WebSocket 实现前后端实时通信，提供良好的用户体验
