## 6. 用户指南

### 6.1 系统概览

YL-analysis 是一个功能强大的代码安全分析工具，专为开发人员和安全审计人员设计，旨在自动化检测代码中的潜在漏洞和安全问题。本用户指南将详细介绍系统的使用方法，帮助用户充分利用 YL-analysis 的各项功能。

系统主界面由顶部导航栏、左侧菜单、主内容区和底部状态栏组成。顶部导航栏显示系统标题和主要功能区域切换按钮；左侧菜单包含项目管理、分析管理、设置等功能入口；主内容区显示当前功能的详细内容；底部状态栏显示系统状态、版本信息等。

### 6.2 快速入门

#### 6.2.1 访问系统

1. 打开浏览器，访问 YL-analysis 系统地址（默认为 `http://localhost:5000`）
2. 系统不需要登录，直接进入主界面

#### 6.2.2 基本工作流程

YL-analysis 的基本工作流程包括以下步骤：

1. 上传项目：在「项目管理」页面上传待分析的代码项目
2. 启动分析：选择项目和漏洞类型，启动分析任务
3. 查看结果：在「漏洞分析」页面查看分析结果，包括调用图和漏洞详情
4. 修复漏洞：根据分析结果和修复建议，修复代码中的漏洞

### 6.3 项目管理

项目管理是 YL-analysis 的基础功能，用于管理待分析的代码项目。

#### 6.3.1 查看项目列表

1. 在左侧菜单中点击「项目管理」
2. 系统将显示所有已上传的项目列表
3. 列表中包含项目名称、上传时间、文件大小等信息

#### 6.3.2 上传新项目

1. 在项目列表页面，点击「上传项目」按钮
2. 在弹出的对话框中，点击「选择文件」或将文件拖拽到指定区域
3. 选择要上传的项目文件夹
4. 可以选择性地修改项目名称
5. 点击「上传」按钮开始上传
6. 上传完成后，项目将出现在项目列表中

**项目文件要求**：
- 文件夹内应包含完整的项目代码
- 支持的编程语言：Python, Java, JavaScript, PHP, C/C++, Go 等

#### 6.3.3 查看项目详情

1. 在项目列表中，点击项目名称或「查看」按钮
2. 系统将显示项目的详细信息，包括：
   - 项目基本信息（名称、大小、上传时间等）
   - 文件列表
   - 历史分析记录

#### 6.3.4 删除项目

1. 在项目列表中，找到要删除的项目
2. 点击该项目行右侧的「删除」按钮
3. 在弹出的确认对话框中，点击「确认」按钮
4. 项目将被永久删除（此操作不可撤销）

### 6.4 代码分析

代码分析是 YL-analysis 的核心功能，用于检测代码中的潜在漏洞。

#### 6.4.1 启动分析任务

1. 在左侧菜单中点击「项目管理」
2. 在项目列表中，找到要分析的项目
3. 点击该项目行右侧的「分析」按钮
4. 在弹出的对话框中，选择要分析的漏洞类型（可多选）
5. 点击「开始分析」按钮
6. 系统将创建分析任务并加入队列

#### 6.4.2 查看分析状态

1. 启动分析任务后，系统将自动显示分析状态
2. 分析状态包括：
   - 队列中：任务正在等待执行
   - 运行中：任务正在执行
   - 已完成：任务已完成
   - 已失败：任务执行失败
3. 对于运行中的任务，系统会显示进度条和实时日志

#### 6.4.3 查看分析结果

1. 分析完成后，点击「查看结果」按钮或在左侧菜单中点击「漏洞分析」
2. 选择要查看的项目
3. 系统将显示该项目的分析结果，包括：
   - 调用图：展示函数调用关系
   - 漏洞列表：列出检测到的所有漏洞
   - 漏洞详情：显示选中漏洞的详细信息

### 6.5 调用图分析

调用图分析是 YL-analysis 的特色功能，通过可视化展示函数调用关系，帮助用户理解漏洞的传播路径。

#### 6.5.1 查看调用图

1. 在左侧菜单中点击「漏洞分析」
2. 选择要查看的项目
3. 系统将显示该项目的调用图
4. 调用图中的节点表示函数，边表示调用关系
5. 不同类型的节点使用不同的颜色标识：
   - 红色：源函数（漏洞输入点）
   - 黄色：汇函数（漏洞触发点）
   - 蓝色：普通函数

#### 6.5.2 调用图交互

调用图支持多种交互操作，帮助用户更好地分析漏洞：

- **缩放**：使用鼠标滚轮或触控板手势缩放调用图
- **平移**：按住鼠标左键拖动调用图
- **选择节点**：点击节点选中它，查看详细信息
- **展开/折叠**：双击节点展开或折叠其子节点
- **重置视图**：点击「重置视图」按钮恢复默认视图

#### 6.5.3 查看节点详情

1. 在调用图中点击某个节点
2. 系统将在右侧面板显示该节点的详细信息，包括：
   - 函数名称和路径
   - 函数代码
   - 入度关系（调用该函数的函数）
   - 出度关系（该函数调用的函数）
   - 漏洞信息（如果该函数涉及漏洞）

### 6.6 漏洞分析

漏洞分析是 YL-analysis 的核心输出，提供详细的漏洞信息和修复建议。

#### 6.6.1 查看漏洞列表

1. 在「漏洞分析」页面，系统将显示检测到的所有漏洞列表
2. 漏洞列表包含以下信息：
   - 漏洞类型
   - 威胁评分
   - 漏洞函数
   - 漏洞路径

#### 6.6.2 查看漏洞详情

1. 在漏洞列表中点击某个漏洞
2. 系统将显示该漏洞的详细信息，包括：
   - **漏洞描述**：漏洞的详细描述
   - **威胁评分**：漏洞的严重程度评分（1-10，越高越严重）
   - **漏洞函数**：存在漏洞的函数
   - **利用方式**：漏洞的可能利用方式
   - **修复建议**：修复漏洞的建议和示例代码
   - **分析理由**：系统判断存在漏洞的理由
   - **污点参数**：涉及漏洞的参数
   - **污点操作**：涉及漏洞的操作

#### 6.6.3 查看漏洞链

1. 在漏洞详情中，系统将显示漏洞链，即从输入点到触发点的函数调用路径
2. 漏洞链以列表形式展示，按调用顺序排列
3. 点击漏洞链中的函数，可以在调用图中高亮显示该函数

### 6.7 系统设置

系统设置允许用户配置 YL-analysis 的各项参数，以满足特定的分析需求。

#### 6.7.1 查看系统设置

1. 在左侧菜单中点击「设置」
2. 系统将显示当前的系统设置

#### 6.7.2 修改 LLM 设置

1. 在「设置」页面，找到「LLM 设置」部分
2. 可以修改以下设置：
   - **LLM 提供商**：选择 LLM 服务提供商（OpenAI、Anthropic、本地模型等）
   - **模型选择**：选择使用的模型（GPT-3.5、GPT-4、Claude 等）
   - **API 密钥**：设置 API 密钥
   - **API 基础 URL**：设置 API 服务的基础 URL
3. 修改完成后，点击「保存」按钮

#### 6.7.3 修改分析设置

1. 在「设置」页面，找到「分析设置」部分
2. 可以修改以下设置：
   - **测试模式**：启用/禁用测试模式
   - **重试次数**：设置 API 调用失败时的重试次数
   - **超时设置**：设置 API 调用超时时间
3. 修改完成后，点击「保存」按钮

### 6.8 最佳实践

为了获得最佳的分析效果，建议遵循以下最佳实践：

#### 6.8.1 项目准备

- 确保上传的项目包含完整的代码，包括所有依赖文件
- 移除不必要的二进制文件、临时文件和构建产物
- 确保项目结构清晰，便于系统理解代码组织

#### 6.8.2 漏洞类型选择

- 根据项目特点选择合适的漏洞类型
- 对于大型项目，建议分批次选择不同的漏洞类型进行分析
- 优先选择与项目技术栈相关的漏洞类型

#### 6.8.3 结果分析

- 关注高威胁评分的漏洞，优先处理
- 结合调用图理解漏洞的传播路径
- 参考修复建议，但不要盲目应用，应结合项目实际情况

#### 6.8.4 系统配置

- 使用高质量的 LLM 模型（如 GPT-4）获得更准确的分析结果
- 适当增加超时设置，确保复杂项目能够完成分析
- 定期更新系统，获取最新的漏洞检测能力

### 6.9 常见问题解答

#### 6.9.1 分析任务长时间未完成

**问题**：分析任务启动后长时间处于运行状态，没有完成。

**解决方案**：
- 检查项目大小，过大的项目可能需要更长的分析时间
- 查看系统日志，了解分析进度和可能的问题
- 如果确认任务卡住，可以尝试停止任务并重新启动
- 考虑增加超时设置或使用更强大的硬件

#### 6.9.2 分析结果不准确

**问题**：分析结果中存在误报或漏报。

**解决方案**：
- 检查 LLM 设置，使用更高质量的模型可能提高准确性
- 确保项目代码完整，缺少关键文件可能导致分析不准确
- 尝试不同的漏洞类型，某些漏洞可能需要特定的分析方法
- 提供反馈，帮助改进系统

#### 6.9.3 上传项目失败

**问题**：上传项目时出现错误。

**解决方案**：
- 检查项目大小，确保不超过系统限制
- 确保项目文件夹结构正确
- 检查网络连接和浏览器状态
- 尝试分批上传或压缩后上传

#### 6.9.4 调用图显示不完整

**问题**：调用图中缺少某些函数或调用关系。

**解决方案**：
- 确保项目代码完整，包含所有相关文件
- 检查是否存在动态调用或反射调用，这些可能难以静态分析
- 尝试使用不同的布局算法查看调用图
- 考虑手动添加缺失的调用关系（如果系统支持）
