## 3. 后端 API 设计

### 3.1 API 设计原则

YL-analysis 系统的后端 API 设计遵循以下原则：

1. **RESTful 风格**：API 采用 RESTful 设计风格，使用标准的 HTTP 方法（GET、POST、DELETE 等）表示操作类型，资源路径清晰明了。

2. **JSON 数据格式**：所有 API 请求和响应均使用 JSON 格式，确保数据交换的一致性和可读性。

3. **统一响应格式**：所有 API 响应遵循统一的格式，包含状态码、消息和数据，便于前端处理。

4. **版本控制**：API 路径包含版本信息，便于后续版本升级和兼容性维护。

5. **错误处理**：提供统一的错误处理机制，返回明确的错误代码和描述信息。

### 3.2 API 基础路径

系统的所有 API 均以 `/api` 为基础路径，当前版本为 v1（默认版本，路径中不显式包含版本号）。

### 3.3 统一响应格式

所有 API 响应均遵循以下格式：

```json
{
  "status": "success",  // 或 "error"
  "message": "操作成功",  // 成功或错误消息
  "data": {}  // 响应数据，可能是对象、数组或 null
}
```

### 3.4 API 接口详情

#### 3.4.1 项目管理接口

##### 获取项目列表

- **URL**: `/api/list-challenges`
- **方法**: GET
- **描述**: 获取所有已上传的项目列表
- **参数**: 无
- **响应示例**:

```json
{
  "status": "success",
  "message": "获取项目列表成功",
  "data": [
    {
      "name": "project1",
      "created_at": "2023-05-01T12:00:00Z",
      "size": 1024
    },
    {
      "name": "project2",
      "created_at": "2023-05-02T14:30:00Z",
      "size": 2048
    }
  ]
}
```

##### 上传项目

- **URL**: `/api/upload-folder`
- **方法**: POST
- **描述**: 上传新项目文件夹
- **参数**: 
  - `file`: 项目文件（multipart/form-data）
  - `name`: 项目名称（可选，默认使用文件名）
- **响应示例**:

```json
{
  "status": "success",
  "message": "项目上传成功",
  "data": {
    "name": "project1",
    "created_at": "2023-05-01T12:00:00Z",
    "size": 1024
  }
}
```

##### 删除项目

- **URL**: `/api/delete-project/{project_name}`
- **方法**: DELETE
- **描述**: 删除指定项目
- **参数**: 
  - `project_name`: 项目名称（路径参数）
- **响应示例**:

```json
{
  "status": "success",
  "message": "项目删除成功",
  "data": null
}
```

#### 3.4.2 分析管理接口

##### 启动分析任务

- **URL**: `/api/start-analysis`
- **方法**: POST
- **描述**: 启动项目分析任务
- **参数**: 
  - `project_name`: 项目名称
  - `vuln_type`: 漏洞类型（可选，默认分析所有类型）
- **响应示例**:

```json
{
  "status": "success",
  "message": "分析任务已启动",
  "data": {
    "task_id": "task-123",
    "status": "queued"
  }
}
```

##### 获取分析状态

- **URL**: `/api/analysis-status`
- **方法**: GET
- **描述**: 获取当前分析任务的状态
- **参数**: 无
- **响应示例**:

```json
{
  "status": "success",
  "message": "获取分析状态成功",
  "data": {
    "current_task": {
      "project_name": "project1",
      "vuln_type": "Command_injection_CWE_78",
      "status": "running",
      "progress": 0.5
    },
    "queue": [
      {
        "project_name": "project2",
        "vuln_type": "SQL_injection"
      }
    ]
  }
}
```

##### 停止分析任务

- **URL**: `/api/stop-analysis`
- **方法**: POST
- **描述**: 停止当前正在执行的分析任务
- **参数**: 无
- **响应示例**:

```json
{
  "status": "success",
  "message": "分析任务已停止",
  "data": null
}
```

##### 获取分析结果

- **URL**: `/api/call-graph/{project_name}`
- **方法**: GET
- **描述**: 获取指定项目的分析结果
- **参数**: 
  - `project_name`: 项目名称（路径参数）
- **响应示例**:

```json

  "message": "获取分析结果成功",

      {
        "id": 1,

      "存在漏洞": true,
```

### 3.5 错误处理

当 API 请求出现错误时，系统将返回统一格式的错误响应：

```json
{
  "status": "error",
  "message": "错误描述信息",
  "error_code": "ERROR_CODE",
  "data": null
}
```

#### 常见错误代码

| 错误代码 | 描述 |
|---------|------|
| `INVALID_REQUEST` | 请求参数无效 |
| `PROJECT_NOT_FOUND` | 项目不存在 |
| `UPLOAD_FAILED` | 项目上传失败 |
| `ANALYSIS_FAILED` | 分析任务失败 |
| `TASK_NOT_RUNNING` | 没有正在运行的任务 |
| `INTERNAL_ERROR` | 内部服务器错误 |

### 3.6 API 认证

当前版本的 API 不需要认证。在生产环境中，建议实施适当的认证机制以保护 API 安全。

### 3.7 API 版本控制

当前 API 版本为 v1（默认版本）。未来版本更新时，将在路径中显式包含版本号，如 `/api/v2/...`。
