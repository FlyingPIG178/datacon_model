## 1.梯形调用（数据驱动添加边）

### 遍历每个函数体（`func.body`）

```
lines = func.body.strip().splitlines()
```

把多行的函数体变成一行一行处理，便于逐句分析。

------

### 2. 识别语句 `x = b()`

```
assign_match = re.match(r"(\w+)\s*=\s*(\w+)\s*\(.*\)", line)
```

- `(\w+)`：变量名 `x`
- `(\w+)()`：调用的函数 `b()`

如果匹配上了，说明该语句是：

> “某个函数 `b()` 的返回值赋值给变量 `x`”

我们就记录这个映射关系：

```
var_source_map[x] = b
```

------

### 3. 识别语句 `c(x)` 或 `c(x, y)`

```
call_match = re.match(r"(\w+)\s*\(([^)]*)\)", line)
```

如果调用了某个函数 `c()`，我们就取出所有参数，比如 `x`、`y`。

然后判断：

```
if arg in var_source_map:
    source_func = var_source_map[arg]
    edges.append((source_func, callee))  # 生成 b → c
```

说明这个 `arg` 是从前面函数 `b()` 返回来的，那我们就建立一条数据驱动调用边：

> **“谁返回了这个值 → 谁用了这个值”**

## 3，不要拘泥于梯形调用的问题

为什么不得到最短链（source到sink）再从头遍历到尾，判断中间的调用关系，然后再构建一个调用链，最后以调用链trace的格式交给大模型呢

# 代码迁移更新计划

### 步骤总结：

1. **初始调用链：** 用 CodeQL 得到从 `entry → ... → sink` 的路径（用 `getACallNode*()` 或 `taint path`）
2. **逐函数遍历：**
   - 查找该函数体中调用了哪些其他函数
   - 是否存在“对污点参数”的操作函数（如 `sanitize`）
3. **递归补链：**
   - 对于每个处理函数（`sanitize`）：
     - 继续深入分析它是否还调用其他处理函数（嵌套清洗）
     - 把这些子调用作为子节点加入 JSON
4. **每个节点记录：**
   - `function`: 函数名
   - `taint_actions`: 针对污点参数的操作（静态判断或抽象）
   - `calls`: 子函数递归结构

### 你有这样的代码：

```
void entry() {
    char input[100];
    fgets(input, 100, stdin);   // ✅ source：input
    process(input);
}

void process(char *data) {
    sanitize(data);             // ✅ 中间清洗
    execute(data);              // ⚠️ 终点使用
}

void execute(char *cmd) {
    system(cmd);                // ⚠️ sink：cmd
}
```
